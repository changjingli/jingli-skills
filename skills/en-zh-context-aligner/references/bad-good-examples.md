# Paired Examples (好味道 vs 坏味道测试集)

Use these pairs to calibrate taste and extract reusable cognitive routing rules.

## Case 1: 极端量词的【否定转化规约】

- ❌ **坏味道（翻译腔）**：打造并交付一个带有 0 行手动编写代码的软件内部测试版。
- 🟢 **好味道（直觉内化）**：全程没手写过一行原生代码，直接硬核交付了一款内测版软件。
- 💡 **认知审计**：中文里的“带有 0 行手动编写代码”极度反人类。把极端量词改写成带情绪的否定句“没手写过一行”，并把 `shipping` 按产品语境对齐为“交付/发版”。

## Case 2: 文化色彩词的【意象重构规约】

- ❌ **坏味道（翻译腔）**：我们正在寻找野心勃勃的工程团队来和我们一起建立这个。
- 🟢 **好味道（直觉内化）**：我们正在寻找有野心、敢破局的工程团队与我们共建。
- 💡 **认知审计**：中文里的“野心勃勃”常带贬义；硅谷创投语境中的 `ambitious` 更接近“不甘平庸、敢做 10x 创新”。用“敢破局”等中性偏褒义词对齐，并把含混的 `build this` 落成“共建”。

## Case 3: 经典翻译腔句式的【结构重排规约】

- ❌ **坏味道（翻译腔）**：这使得 Node.js 成为一个具有非常高性能的工具，它是 Google Chrome 的核心。
- 🟢 **好味道（直觉内化）**：正因继承了 Google Chrome 底层核心 V8 的强悍基因，Node.js 拥有极佳的性能表现。
- 💡 **认知审计**：原句的 `This allows` 因果指代含混，技术事实也容易误读。Node.js 不是 Chrome 的核心，而是运行在 V8 引擎之上。重构时先补全技术因果，再按中文“大帽子戴在前面”的习惯把背景前置，消除“具有……性能”的翻译腔。

## Mechanical Bad Smells

- `带有 0 行`、`0 行代码`、`零行代码`
- `具有...性能`
- `是...的其中之一`
- `被认为...`
- `被期望...`
- `对于...而言`
- `建立这个`
- 招募语境中的 `野心勃勃`
